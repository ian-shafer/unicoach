### The canonical money store, as it constrains this work

| Table                | Key                                                                                          | Relevant shape                                                                                                                                                                                                                                                              |
| -------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `price_figures`      | `UNIQUE (college_id, price_concept, residency_basis, arrangement, academic_year)`            | a PRICE a school charges; `academic_year` `CHECK ~ '^[0-9]{4}-[0-9]{2}$'`; value iff status ∈ {`reported`,`imputed_by_publisher`} (`db/schema/0083...sql:184-245`)                                                                                                          |
| `cohort_money_stats` | `UNIQUE (college_id, measure, population, residency_scope, aid_scope, income_band, vintage)` | an outcome over a COHORT; `measure` is a closed CHECK list of 5 (`avg_net_price`, `published_cost_blend`, `pell_share`, `median_debt_at_completion`, `median_earnings_10y`), `population` a closed list of 4, `vintage` `'^[0-9]{4}-[0-9]{2}$'` or `'undated'` (`:247-285`) |
| `aid_policy_facts`   | `UNIQUE (college_id, policy, academic_year)`                                                 | school aid policy, closed `policy` list (`:324-350`)                                                                                                                                                                                                                        |
| `figure_statuses`    | vocabulary, `value_bearing`                                                                  | `reported`, `imputed_by_publisher`, `not_reported_by_institution`, `not_applicable`, `suppressed_by_publisher`, `not_collected_by_us` (`db/.../models/FigureStatus.kt:16-34`)                                                                                               |
| `AssuranceTier`      | `(MoneySource, source_variable)` → tier                                                      | `SCORECARD_TIERS` is a literal 24-key map; an unregistered variable is a typed fault (`db/.../models/AssuranceTier.kt:90-125`; `ScorecardInstitutionColumns.kt:271-281`)                                                                                                    |

**The answer to the central question: these figures do NOT belong in either fact
table, and they DO belong in the canonical store's shape.** Concretely:

- Every axis of `cohort_money_stats`' uniqueness key is institution-level. A
  field-of-study figure has **two more axes** (`cip_code`, `credential_level`),
  so it cannot be stored without changing the primary grain of a table that its
  CHECK block (`:263-285`), `canonical_money_summary`, `CanonicalMoneyDao`,
  `CanonicalMoneyReadDao` and the search-index rebuild all read as
  one-row-per-college. Adding nullable `cip_code`/`credential_level` to it would
  make every existing reader's `WHERE` clause silently wrong (a query for
  `median_earnings_10y` would start matching per-field rows) — the RFC 155 class
  of defect, in a read-then-serve path.
- It is not `price_figures` either: nobody charges it, and `academic_year`
  cannot hold "AY2017-18 + AY2018-19 pooled, measured CY2022-23, in 2024
  dollars".
- It **is** a cohort statistic in kind, so it wants a **sibling fact table** —
  say `program_money_stats`, keyed
  `(college_id, cip_code, credential_level,
  measure, vintage)` — that
  **reuses** `figure_statuses` (FK), `source` + `source_variable`,
  `publisher_flag`, and the `value IS NOT NULL = status IN
  (value-bearing)`
  CHECK. That is the same store, one table wider, and it leaves
  `median_earnings_10y` (institution, Treasury, pooled, `undated`) untouched
  beside it.

`CanonicalMoneyLoader.kt` is 1,978 lines and already owns the Scorecard fill,
`ORDERED_SOURCES`, and the vintage constants (`:1659` `PUBLISHED_PRICE_YEAR`,
`:1668` `BLENDED_AVERAGE_VINTAGE`, `:1741` `VINTAGE_UNDATED = null`). The
field-of-study fill is a new phase reading a different file at a different
grain; putting it in that file is a merge-risk decision, not a correctness one
(Q5).
